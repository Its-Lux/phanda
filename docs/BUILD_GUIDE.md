# Build Guide — Feature-Sliced Vite + React + TanStack Query App

This document records how this application was built, in order, and why each
decision was made. It is a living document — update it as each phase is
completed so it stays an accurate record of the actual build, not just the plan.

**Status legend:** `[ ]` not started · `[~]` in progress · `[x]` done

---

## Phase 0 — Project Initialization

- [x] Scaffold with Vite (React + TypeScript template), installed via Yarn
- [x] Initialize git, first commit
- [x] `.gitignore`, `.editorconfig`
- [x] Node version pinned (`.nvmrc` / `engines` field) — Node 24.18.0
- [x] Yarn version confirmed intentional — Yarn Classic 1.22.22

**Why:** Establishes a clean, reproducible starting point before any
architecture decisions are layered on.

---

## Phase 1 — Tooling & Project Config

- [x] TypeScript strict mode configuration
- [x] Path aliases (`@/features/*`, `@/app/*`, etc.) in `tsconfig.json` + `vite.config.ts`
- [x] ESLint (flat config) + Prettier
- [x] Tailwind CSS v4 installed via the `@tailwindcss/vite` plugin (v4 drops
      the old `tailwind.config.js` + PostCSS setup in favor of CSS-based
      config via `@theme`)
- [x] Environment variables (`.env`, `.env.example`, typed via `import.meta.env`)
- [x] Pre-commit hook (husky + lint-staged)

**Why:** Tooling decided now prevents inconsistent imports and style drift
once multiple features exist.

---

## Phase 2 — Base Folder Structure

- [x] `src/app/` — app shell, providers, router, global config
- [x] `src/features/` — vertical slices (empty, ready for first feature)
- [x] `src/shared/` — cross-feature primitives only (ui kit, generic utils) —
      _deliberately minimal_, since the constraint is "everything a feature
      needs lives inside the feature"
- [x] Barrel export convention decided (per-feature `index.ts`)

**Why:** Locks in the feature-sliced convention before code accumulates in
the wrong place.

---

## Phase 3 — App Shell & Providers

- [x] Root `App.tsx`
- [x] `QueryClientProvider` (TanStack Query) set up in `app/`
- [x] React Query Devtools wired in dev mode only
- [x] Global error boundary
- [ ] (Optional) TanStack Router provider + root route — deferred, not part of base

**Why:** Providers belong at the app level, not inside features — this is
the one exception to "everything lives in the feature."

---

## Phase 4 — First Feature Slice (reference implementation: `todos`)

- [x] `types/` — domain types
- [x] `api/` — raw HTTP calls (fetch/axios), no business logic
- [x] `services/` — data shaping / transforms between API and app
- [x] `hooks/` — `useQuery` / `useMutation` wrappers, query key factory
- [x] `store/` — client/UI-only state (Zustand), never server state
- [x] `components/` — presentational + connected components
- [x] `pages/` — route-level composition
- [x] `libs/` — feature-local helpers that don't fit elsewhere
- [x] Feature `index.ts` barrel (public surface of the feature)

**Why:** This becomes the template every future feature copies. Getting the
dependency direction right here (`pages → hooks → services/api/store`)
matters more than the feature's actual content.
